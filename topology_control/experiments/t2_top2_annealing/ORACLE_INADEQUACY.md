## Первый прогон дал `SUCCESS` — и это артефакт

```
rings=30, steps=500, seed=42
Initial          C = 1.50
random           C = 9.00
angle            C = 4.50
angle+curvature  C = 4.50
advantage_score = 0.5000  ->  формально SUCCESS
```

Сработал **Switch 1 «Too Beautiful To Be True»** из `KILL_CRITERIA.md`: успех с первого
прогона, обе biased-модели дали *побитово одинаковый* результат. Проверка вместо
празднования вскрыла три дефекта.

### Дефект 1 — «преимущество» есть бездействие

[VERIFIED, прогон 2026-08-29, seed=42, 500 шагов]

| Модель | Принято passages | Средняя p |
|---|---|---|
| random | **233 / 500** | 0.5000 |
| angle | **29 / 500** | 0.0448 |
| angle+curvature | **29 / 500** | 0.0448 |

Biased-модели принимают в **8 раз меньше** движений. При этом «passage» в модели —
не смена топологии, а случайный сдвиг кольца на 0.2 (`toy_model.py:211-212`), который
способен только перемешивать конфигурацию. Меньше движений → меньше перемешивания →
ниже финальная сложность.

`advantage_score = C_biased / C_random` вознаграждает **низкую частоту принятия**, а не
топологическое упрощение. Гипотеза T2 утверждает, что TOP2 достигает упрощения
локальными правилами; измеряемая величина к этому утверждению не привязана.

Симптом виден и в самих числах: baseline **ухудшил** сложность с 1.50 до 9.00. Ни одна
модель не опустилась ниже стартовой сложности. Упрощения не произошло нигде — метрика
всё равно рапортует SUCCESS.

### Дефект 2 — модель 3 не существует

[VERIFIED-CODE]

`toy_model.py:198` жёстко задаёт `crossing_point = 0`. В
`topology_utils.py:317-319` ветка кривизны начинается с:

```python
i = crossing_point          # = 0
if i < 2 or i >= len(ring1) - 2:
    return p_angle          # кривизна не применяется
```

При `i = 0` условие `i < 2` истинно всегда → `strand_passage_curvature_bias` возвращает
`p_angle` без изменений. **Модель «angle+curvature» — побитовый дубликат модели «angle».**
Отсюда одинаковые 29/500 и одинаковые C = 4.50.

Следствие для критериев: `num_params = 2` в анализе неверно — второй параметр
(`β_curv`) не влияет ни на что. Из трёх заявленных моделей реально сравниваются две.

### Дефект 3 — нет позитивного контроля

В эксперименте нет прогона, который **обязан** показать упрощение. Без него невозможно
отличить «правило работает» от «метрика измеряет что-то другое» — что и произошло.

## Почему это `ORACLE_INADEQUATE`, а не `KILL`

`rules/falsification-ladder.md` Step 2b, жёсткое правило:

> `ORACLE_INADEQUATE` — статус, отличный от PROMOTE/REPEAT/REJECT, и он **никогда не
> записывается как свидетельство против claim**, даже когда сырая метрика выглядит
> благоприятно. «Оракул не смог различить» ≠ «гипотеза провалилась».

Гипотеза T2 (TOP2 использует локальные правила strand passage для глобального снижения
топологической сложности) **не проверена**. Инструмент измеряет частоту принятия
движений, а не топологию.

Записать это как SUCCESS было бы хуже всего: `KILL_CRITERIA.md` ставит
`T1 depends on T2 SUCCESS`, а Phase 2 открывается при `≥1 SUCCESS` в Phase 1. Ложный
успех T2 разблокировал бы весь каскад на артефакте.

---

## Что нужно, чтобы T2 стал проверяемым

По убыванию важности:

1. **Passage обязан менять топологию.** Сейчас это случайная трансляция. Нужна операция,
   которая реально переставляет нити в точке пересечения и меняет linking number —
   иначе «отжиг» физически невозможен в модели.
2. **`crossing_point` должен находиться, а не задаваться нулём.** Требуется детекция
   реальной точки пересечения пары колец; без неё обе biased-модели вырождаются в одну.
3. **Метрика должна сравниваться со стартом, а не только между моделями.** Минимум:
   `C_final < C_initial` как необходимое условие — упрощение обязано произойти.
4. **Позитивный контроль.** Конфигурация с заранее известным разрешимым сцеплением
   (например, Hopf link, где корректный passage обязан дать `Lk: 1 → 0`).
5. **Число принятых passages — обязательная выходная метрика.** Именно она вскрыла
   дефект 1 и должна публиковаться рядом с `advantage_score`, иначе артефакт снова
   пройдёт незамеченным.

До пункта 1 включительно любой результат T2 нельзя интерпретировать ни в одну сторону.

## Статус в реестре

`T2 / H-TOPO-2` остаётся **не опровергнутой**. Меняется только причина остановки:

| Было | Стало |
|---|---|
| `POSTPONED` — не хватает производительности | `ORACLE_INADEQUATE` — производительность есть, измеритель не годится |

переписывания модели passage, а не оптимизации.
