# Claim R3 — факториальная абляция: что порождает остаточные 14.2%

## Исходный R3 опровергнут ДО запуска

`decision_r2.md` назвал единственным кандидатом «тяжесть хвоста логнормали при конечном N».
Рой проб 2026-08-31 (`wvm32g576`) опроверг его **двумя независимыми методами**:

| Метод | Что даёт конечное N при N=200 |
|---|---|
| аналитика + Монте-Карло на `Σ max(0, λ−mean)` | **0.25–0.53%** |
| смещение плагин-оценки той же статистики | **−0.23…−0.67%** |

Нужно 14.2%; для этого потребовалось бы **N ≈ 10**, в модели N = 200. Разрыв ~30-кратный.
**R3 в исходной формулировке закрыт**, и этот файл его переопределяет.

Побочно установлено: `Σ max(0, λ_i − mean)/Σλ_i` — это **индекс Гувера** (Hoover 1936),
с замкнутой формой `H(s) = 2Φ(s/2) − 1` для логнормали. Отвечает на R5.

## Три конкурирующих кандидата, ни один не проверен внутри проекта

| | Фактор | Основание подозревать | Измерено кем |
|---|---|---|---|
| **M** | нелинейность `count_events` (порог + шаги) | в движке БЕЗ этого слоя мультипл. разброс падает 27% → ≤4.4%, аддитивный меняет ЗНАК | проба роя, другой код |
| **C** | обрезка `sensed = np.maximum(sensed, 1e-6)` | затрагивает **22.2%** элементов при CV=1.0 и **34.2%** при CV=2.0 в точках безубыточности | проба роя, аналитически |
| **F** | семейство распределения (логнормаль) | гамма при том же mean и CV даёт разброс **72.3%** / **82.8%** вместо 27.0% / 14.2%, знак переворачивается | проба роя, на коде проекта |

Каждый из трёх измерен как двигающий цель **сильнее**, чем сам объясняемый остаток.

## Дизайн

Факториал **2×2×2 × 4 CV**, только аддитивный арм (тот, где остаток 14.2%):

```
M0 = count_events(loads, cap, STEPS, THRESHOLD)   M1 = Σ max(0, λ_i − cap_i)   [детерм. дефицит]
C0 = np.maximum(sensed, 1e-6)                     C1 = пересэмплировать отрицательные
F0 = логнормаль                                   F1 = гамма (тот же mean, тот же CV)
CV ∈ {0.25, 0.5, 1.0, 2.0}
```

**Seeds расщеплены на две независимые половины: 0–29 и 30–59.** Обязательно, потому что
проба роя показала: `make_loads` строит все CV из одного потока стандартных нормалей,
поэтому четыре колонки — одна реализация хвоста под четырьмя углами, а не 120 независимых.

**Персистить то, что `run_r2.py` выбрасывает:** полная кривая `advantage(noise)` на каждый
CV, значения по каждому seed, доля обрезанных элементов, число пересечений уровня 1.0.
Сейчас `result_r2.json` содержит 4 ключа, кривые уничтожены — половина гипотез из-за
этого принципиально непроверяема.

## Замороженное правило решения

Метрика — **разброс отношения** `noise_breakeven / CV_pop` по четырём CV, как в R1/R2.
Базовая конфигурация M0·C0·F0 воспроизводит 14.2% (позитивный контроль).

| Порог | Значение | Обоснование |
|---|---|---|
| Фактор признаётся **причиной** | снятие его роняет разброс **< 5%** | уже объясняемых 14.2% и уже допуска R2 (10%) |
| Фактор признаётся **частичным вкладом** | разброс падает, но остаётся ≥ 5% | |
| Фактор **не при чём** | разброс не меняется в пределах ±2 п.п. | |

**Порог 5% поставлен УЖЕ объясняемого эффекта** — прямое исполнение паттерна
`[AVOID×4] критерий, который невозможно провалить` (`~/.claude/memory/patterns.md`,
2026-08-31). При допуске «фактор 2» все три фактора «прошли бы».

**Возможен исход «ни один фактор не роняет разброс ниже 5%»** — тогда причина вне трёх
названных, и это валидный KILL для всей тройки сразу.

## Вторичный вопрос: немонотонность — сигнал или шум?

`decision_r2.md` объявил возврат при CV=1.0 (0.950 → 0.972) «независимым указанием на
другой механизм», и на этом стоял приоритет R3. Две пробы роя оценили его как **0.9σ**
и **1.5–1.9σ** — статистически не установлен.

> Замороженный тест: возврат воспроизводится в **обеих** половинах seed при **≥ 3σ**?

Если нет — немонотонность была шумом, и обоснование приоритета R3 отпадает задним числом.
