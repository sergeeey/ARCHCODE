# Claim H1 — специфичность на органеллу, а не скорость

## Что изменилось относительно записи в `KILL_CRITERIA.md` (2026-04-25)

| | Было | Здесь |
|---|---|---|
| Механизм | локальное управление **быстрее** | локальное **адресное**: отклик на состояние своей органеллы |
| Решающий параметр | `τ_ratio = 100` | **`τ_ratio = 1`** — задержки равны, преимущества по скорости нет вообще |
| Основание | — | CoRR Аллена (`novelty_check.md`) + измеренное `τ_real ≈ 2–5` (`source_register.md`) |

**Почему решающий тест при `τ_ratio = 1`:** измерено, что скорость даёт фактор 2–5, а
не 100 — митохондриальная трансляция в 10–16 раз медленнее цитозольной. Такой выигрыш
не окупает содержания отдельного генома. Значит если преимущество вообще есть, оно
не в скорости, и проверять надо там, где скорости нет.

## Модель

```
N органелл. У каждой своя скорость производства ROS λ_i (гетерогенность — CV).
Общий бюджет мощности контроллера C_total ОДИНАКОВ во всех армах.
Событие = уровень ROS органеллы превысил порог θ.

arm  local    : мощность распределяется ПРОПОРЦИОНАЛЬНО собственной нагрузке органеллы
arm  nuclear  : мощность распределяется РАВНОМЕРНО (C_total/N) — контроллер не различает
arm  null     : та же система, но CV = 0 (все λ_i равны среднему)
```

**Ключевое ограничение — равный бюджет.** Без него локальный арм выигрывал бы просто
имея больше ресурса, и это была бы та же тавтология, что с задержкой. Здесь армы
отличаются **только распределением**, не количеством.

**Почему при CV = 0 преимущества обязано не быть:** если все органеллы одинаковы,
пропорциональное распределение тождественно равномерному. Это и есть нулевая модель,
и она даёт `advantage = 1.0` **по построению**.

## Метрика и замороженные пороги

```
advantage(CV)     = events(nuclear) / events(local)
advantage_excess  = advantage(CV > 0) / advantage(CV = 0)
```

| Порог | Значение | Источник |
|---|---|---|
| SUCCESS | `advantage_excess ≥ 1.20` | `AMENDMENTS.md` A-005 |
| KILL | `advantage_excess < 1.05` | A-005 |
| Серая зона | `[1.05, 1.20)` | → INCONCLUSIVE, **стоп и доклад** |

**n = 30 seed, решение по МЕДИАНЕ.** Не среднее, не лучший seed.

## ⚠️ Почему этот критерий МОЖЕТ быть провален — и это не очевидно заранее

Исход зависит от **выпуклости** функции «число событий от нагрузки», а её я не считал:

| Форма зависимости | Что выгодно | Итог |
|---|---|---|
| **линейная** | распределение **не важно вообще** | `excess = 1.0` → **KILL** |
| вогнутая | выгодно размазывать равномерно | `excess < 1` → KILL |
| выпуклая | выгодно бить точечно | `excess > 1` → возможен SUCCESS |

Если суммарное число событий линейно по остаточной нагрузке, оно **инвариантно
к распределению**, и адресность не даёт ничего. Это реальный, не декоративный исход.

Записано до прогона: я **не знаю**, в какую сторону выйдет, и не выбирал модель под
ответ. Порог θ введён как единственный источник нелинейности.

## Вторичное предсказание (диагностическое, на вердикт не влияет)

Если механизм — именно специфичность, преимущество обязано **расти с гетерогенностью**:

> `advantage_excess(CV = 1.0) > advantage_excess(CV = 0.25)`

Если преимущество есть, но от CV не зависит — источник не в адресности, и любой
положительный результат требует другого объяснения.

## Стоимость: не назначаю число, а считаю точку безубыточности

`cost_ratio` (содержание отдельного генома, миторибосом, аппарата трансляции) —
**[UNKNOWN]**, значения в литературе не искал и не имею. Поэтому вместо выдуманного
числа сообщается **порог безубыточности**:

```
какой cost_ratio обнуляет преимущество?   net_benefit = advantage_excess − cost_ratio = 1.0
```

Это честнее: читатель подставит свою оценку стоимости. Назначить cost_ratio самому
означало бы выбрать исход.

## Контроли

| Контроль | Ожидание | Провал означает |

| **Нулевой (он же калибровка)** | при CV = 0 `advantage = 1.00 ± 0.02` | модель не откалибрована → `BLOCKED-INFRASTRUCTURE`, не KILL |
