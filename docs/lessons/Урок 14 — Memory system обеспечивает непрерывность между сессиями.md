# Урок 14 — Memory system обеспечивает непрерывность между сессиями

## Что произошло правильно

За полгода работы мы провели десятки сессий с Claude. activeContext.md, decisions.md и memory files позволяли каждой новой сессии начинать с полного контекста: что сделано, какие решения приняты, какие числа каноничны.

## Конкретные результаты

- activeContext.md содержал точные числа (20 pearls, p=4e-6, d=2.1) — не нужно было каждый раз пересчитывать
- decisions.md хранил 24 ADR — ни одно решение не было забыто или противоречиво пересмотрено случайно
- endorser_plan.md позволял отслеживать статус 10 контактов без потери информации
- commercialization_guardrails.md предотвращал drift в сторону преждевременной продуктизации

## Правило на будущее

Для любого долгосрочного проекта с AI: memory system окупается с третьей сессии. Без него каждая сессия начинается с нуля. С ним — кумулятивный прогресс.

## Как применять

Минимальный набор для нового проекта:
- activeContext.md — что делаем сейчас (обновлять каждую сессию)
- decisions.md — ADR (обновлять при каждом архитектурном решении)
- MEMORY.md — индекс всех memory files
- Формат: frontmatter (name, type, description) + content
- Правило: обновлять в конце каждой сессии, не "потом"
