# Урок 18 — Костыль в тесте маскирует архитектурный дефект

## Что произошло

ChernoffPy Heston PDE взрывался при T=5.0, n_steps=50. CFL ratio = 16.13 при target 0.5. Fix: n_steps 50->200 в тесте. Тесты стали зелёными. Аудит закрыл блокер.

Skeptic Engine проверил: это не "плохой параметр в тесте", а **системная нестабильность метода**. 33 sub-iterations в explicit Euler substepping недостаточно при CFL=16. Фикс замаскировал проблему, не решил.

## Правило

Когда тест падает на определённых параметрах — спроси: "это баг в тесте или ограничение метода?" Если ограничение метода — не меняй тест, а:
1. Добавь warning/error в API при опасных параметрах
2. Задокументируй ограничение
3. Тест пусть проверяет что warning срабатывает

## Паттерн

"Masking systemic issue as parameter issue" — типичный cognitive failure. Тест зелёный = ложное спокойствие. Пользователь с T=5.0 n_steps=50 получит мусор без предупреждения.

## Связь с ARCHCODE

Тот же паттерн: AUC=0.975 выглядел хорошо, но тестировал не то. Зелёные тесты не значат что система работает правильно — они значат что тесты проходят.
