Following up on our March exchange about ARCHCODE. I've completed an independent AlphaGenome CAGE validation on HBB disease variants:

• Promoter pearls: -18% CAGE disruption vs -3.2% benign (p=2.8×10⁻⁴, Mann-Whitney U, N=13 vs N=19)
• Real AlphaGenome API (predict_variant endpoint, SDK v0.6.0 — not mock)
• Falsification-first controls: category-matched, permutation (10K), shuffled labels
• Cross-locus test: MLH1 regulatory works (p=0.022), BRCA1/TP53 coding null (expected)

The 73bp HBB promoter cluster (chr11:5227099-5227172, GRCh38) is a candidate for wet-lab validation. 15/20 structural fragility candidates cluster in this zone.

Honest limitations disclosed upfront:
- Category-matched validation: WEAK (ADR-027, May 8) — 15/20 pearls untestable (no non-pearl promoter controls exist in ClinVar HBB)
- ARCHCODE × AlphaGenome concordance: NULL (ρ=0.077, p=0.67) — orthogonal mechanisms (3D structure vs promoter function)
- Resolution mismatch: AlphaGenome contact maps null on SNVs (2048bp limit)
- Cell-type mismatch: K562 used, HBB expressed in erythroid
- No wet-lab validation yet (all computational)

Given category-matched validation WEAK result (ADR-027), I'm pivoting to ISM hotspot discovery (functional validation, not positional enrichment claim). Would you be interested in collaboration on ISM-based variant prioritization?
